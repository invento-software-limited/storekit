# Changelog

## [1.1.3] - 2026-10-12

### 🐞 Fixed
- Guest checkout on live still threw `PermissionError: No permission for Item`, even after 1.1.2. Traced the full traceback on the production site (ERPNext 16.35.0): `erpnext.stock.get_item_details.get_item_details()` calls `item.check_permission()` directly on a freshly-fetched Item document - a check that `quotation.flags.ignore_permissions` never reaches, since that flag only covers the Quotation's own permission checks, not other doctypes fetched while building it. This explains why it worked in dev (older ERPNext, 16.19.1, without that check) and failed in production the moment a brand new Website User, with no role granting Item read, tried to check out as a guest. `storekit.webshop_functions.cart.place_order` now runs its quotation building, pricing/tax calculation and submission under a temporary Administrator elevation (`_run_as_system_user()`), restored to the real session user immediately after, so checkout no longer depends on which Item (or other business doctype) permissions happen to be configured for a customer's role.
