# Changelog

## [1.1.4] - 2026-10-12

### 🐞 Fixed
- Guest cart showed VAT but it vanished once the same customer logged in. `calculate_taxes_and_totals()` in `storekit.webshop_functions.cart` only applied the default Sales Taxes and Charges Template to a logged-in cart when the Quotation's `tax_category` was set - and ordinary self-registered customers never get a `tax_category` from `get_party()`, so their carts silently computed £0.00 tax. The guest-cart branch (no Quotation yet) had no such gate and always applied the default template, which is why the mismatch only showed up after login. Logged-in carts now fall back to the default template the same way guest carts do.
- Logging in with items already in the guest cart could add duplicate quantities instead of replacing them, and could leave a line stuck at £0.00. `_merge_guest_cart()` in `storekit.webshop_functions.checkout_auth` now clears the quotation's items and re-appends exactly what's in the guest cart (instead of incrementing matching rows against whatever the saved cart already had), resets `rate`/`price_list_rate`/`amount` to `None` before re-pricing so a previously-zeroed row gets a fresh price list lookup, and runs the re-pricing/save under `_run_as_system_user()` since a brand-new Website User may lack Item read permission for `set_missing_values`.

### ✨ Added
- Cart side-drawer now actually populates. The drawer markup (`#cart-section` / `#cart-item-template` / `#cart-container`) existed on every page already, but nothing called the cart APIs to fill it in, so it always showed the static "Your cart is empty" placeholder regardless of the cart-count badge. Added `storekit/cart-drawer.js` and the matching Builder client script to wire it up, including its qty +/-/Remove controls.
