# Changelog

## [1.1.1] - 2026-10-12

### 🐞 Fixed
- Guest checkout signup (`storekit.webshop_functions.cart.place_order`) created the new Customer without a Portal User row, so `/profile` showed no order history for a customer who had just signed up and ordered — not then, not ever, since nothing ever added the row later. `create_party()` now links the new Customer to the signing-up user the same way `storekit.api.register.register` already did.
- The same checkout signup could leave two Contact records for one email: Frappe auto-creates a bare Contact for every new User via a background job (`frappe.core.doctype.user.user.create_contact`, enqueued after commit), which could race storekit's own Contact creation in `create_contact()`. `get_contact_name()` has no defined order between the two rows, so `get_party()` sometimes resolved the unlinked one on a later visit, silently creating a second, empty Customer. That Customer's address didn't match the one saved at signup, so placing a second order while logged in failed with "Billing Address does not belong to &lt;customer&gt;" (surfaced to the customer as a generic "Something went wrong"). Added `_resolve_contact_for_email()`, which prefers whichever Contact for an email is actually linked to a party, and used it in `get_party()`, `create_contact()` and `_get_cart_quotation()` instead of trusting `get_contact_name()`'s arbitrary pick.
